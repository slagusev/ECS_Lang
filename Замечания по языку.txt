ECSLang — это язык общего назначения с ECS как философской основой. Всё — игры, GUI, сеть, файлы — реализуется через ECS-парадигму.
Критические фичи (усиливают ECS-философию)
Динамические массивы Vec<T>
Без них невозможно хранить списки сущностей, компоненты с переменным размером
Это база для всех коллекций в ECS
Управление памятью строк
Аренный аллокатор на World идеально вписывается в ECS-парадигму
Каждый мир имеет свою арену, очищается при уничтожении мира
Строки как часть ECS-данных
HashMap<K, V> (приоритет выше, чем я думал)
Для индексации сущностей по именам/тегам
Для кешей ресурсов (текстуры, звуки по путям)
Это естественная структура для ECS
Замыкания / лямбды
Для коллбэков в UI (on_click(|e| handle(e)))
Для фильтров запросов (query.filter(|e| e.health > 50))
Для реактивных систем
Generics + Traits
Для обобщённых систем (system Sort<T: Comparable>)
Для переиспользуемых компонентов
Это делает ECS действительно универсальным
Важные фичи (расширяют ECS-парадигму)
Result<T, E> / Option<T>
Для обработки ошибок в ECS-операциях
world.spawn() может вернуть Option<Entity>
load_texture() возвращает Result<Texture, IOError>
Реактивные потоки событий (новая фича)
world.on_click().filter(|e| e.button == LEFT).subscribe(|e| ...)
Композиция событий как данных
Это усиливает ECS-подход к событиям
Системы как значения (новая фича)
let sys = MovementSystem;
pipeline.add_system(sys);
Динамическое построение пайплайнов
Дополнительные фичи (делают ECS удобнее)
GUI-компоненты как часть стандартной библиотеки
Не отдельная подсистема, а набор ECS-компонентов
Button, Text, Image, Slider — все через ECS
Сетевые компоненты
Connection, Packet, Socket — через ECS
Стандартные системы для TCP/UDP

ECSLang — это язык общего назначения с ECS как философской основой. Всё — игры, GUI, сеть, файлы — реализуется через ECS-парадигму.
Развивать ECS-инфраструктуру:
Vec<T>, HashMap<K, V> — для ECS-коллекций
Замыкания — для реактивных систем
Generics — для обобщённых компонентов
Result/Option — для обработки ошибок в ECS
Создать стандартную библиотеку ECS-компонентов:
GUI: Button, Text, Input, Slider
Сеть: Connection, Packet, Socket
Файлы: FileHandle, FileReader, FileWriter
Аудио: AudioSource, AudioListener
Демонстрировать универсальность:
Игра (уже есть)
GUI-приложение (редактор уровней, например)
Сетевой сервер (чат, игровая логика)
Утилита (обработчик данных)
ECSLang — это не "язык для игр". Это язык, где ECS — это способ программировать вообще.
И это делает его действительно уникальным. Ни Rust, ни Go, ни Zig не предлагают ECS как философскую основу. Это ваша киллер-фича.
